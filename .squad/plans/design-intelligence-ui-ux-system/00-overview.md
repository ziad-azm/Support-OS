## Dependency notes

This feature maps to **EPIC 8 — Design Intelligence & UI/UX System** in `SupportOs backlog.MD` (lines 496-524). It depends on `internationalization-design-system` (`UI`, `I18N`) per the epic's own `Depends on` line — see [`../internationalization-design-system/00-overview.md`](../internationalization-design-system/00-overview.md).

**Story 35 (`DSN-0`, Design Intelligence Foundation) is complete.** It is a tooling + documentation story, not app code — it installed the `ui-ux-pro-max` Claude Code skill into this repo (`.claude/skills/ui-ux-pro-max/`), ran its design-system generator once against SupportOS's real product description, persisted the result to `design-system/supportos/MASTER.md` (the skill nests persisted output under `design-system/<project-slug>/`, not the flat `design-system/MASTER.md` the plan assumed), and codified the reusable `DSN` shared spec as a new `CONVENTIONS.md` § 25 — including a token-by-token reconciliation against the existing `UI` tokens in `frontend/src/index.css`, resolving a naming quirk where MASTER.md's color table labels the neutral slate "Primary" while its own component CSS uses the vivid blue labeled "Accent/CTA" as the actual button color. It made **no** code change to `frontend/src/index.css` or any component; that is deliberately deferred to `DSN-1`.

**Story 36 (`DSN-1`, Design System Refresh Across Built Screens) is complete.** It retinted `frontend/src/index.css`'s `--primary`/`--secondary`/`--destructive` tokens and `--font-sans` to `DSN`'s palette/typography (same value in `:root` and `.dark` — a deliberate deviation from the neutral theme's invert-for-dark pattern, justified with real computed WCAG contrast ratios), loaded the Atkinson Hyperlegible font via `frontend/index.html`, and nudged `dialog.tsx`/`alert-dialog.tsx`'s modal corner radius from `rounded-lg` to `rounded-xl` — resolving two of § 25's "Defer" rows (`--secondary`, `--radius`) by reading the actual `button.tsx`/`card.tsx`/`input.tsx` source rather than guessing. `--accent`, `--font-arabic`, and `--chart-*` remain untouched, per § 25's own "Keep current"/"Defer to `DSN-3`" calls. Verified live in a running browser session (login, tickets list, a real delete-confirmation `AlertDialog`), in both light/dark theme.

**Story 37 (`DSN-2`, UX Guidelines & Accessibility Audit) is complete.** Eight verified fixes: real `<h1>`/`<h2>` headings via a `CardTitle` `asChild` addition (`TicketDetailPage`/`CustomerProfilePage` previously had zero headings — confirmed live: `TicketDetailPage` now renders one `<h1>` + 6 `<h2>`s, `CustomerProfilePage` one `<h1>` + 4 `<h2>`s); a new shared `FormErrorSummary` component (`role="alert"`) replacing 11 duplicated, unannounced form-error blocks across 8 files; `cursor-pointer` restored on the shared `Button` (confirmed via computed style, was `default`); `autoComplete="email"`/`"current-password"` on the login form (confirmed via DOM attributes); `title` attributes on 3 truncated-text sites (confirmed on the 3 `SelectField`-routed selects); `role="alert"`/`aria-live="assertive"` on error-toned toasts (confirmed live — a wrong-password login shows an assertive toast, a successful save keeps `role="status"`); a scoped `prefers-reduced-motion` rule for dialog/select entrance-exit animations, confirmed via Playwright's `reducedMotion: 'reduce'` emulation (dialog now opens with no visible zoom/fade) — loading spinners/skeletons untouched. Several guideline categories were audited and found already compliant (alt text, icon-button labels, RTL, wide-table scroll, sortable-header accessibility, field `aria-describedby` wiring, touch target size) — documented in `CONVENTIONS.md` § 25 rather than re-fixed. Bulk row actions and 6 standalone (non-`SelectField`) `SelectTrigger` usages are explicitly named as deferred, not silently dropped. Zero visual regression, zero console errors — `npm run lint`/`format:check`/`check:rtl`/`build` all clean, backend's 54 tests unaffected.

**Story 38 (`DSN-3`, Dashboard Chart Design Guidance) is complete.** A documentation-only story, same shape as `DSN-0` — `Reports & Analytics` (`EPIC 11`) is entirely unbuilt, so there was no chart wrapper, screen, or API to attach a decision to. Verified: `git diff --stat` confined to `CONVENTIONS.md`, `npm run build` and `python manage.py test` (54 passing) both unaffected.

**Story 50 (`DSN-4`, Comprehensive Visual Redesign of Built Screens) is implemented.** It went past `DSN-1`'s token-only swap: three new semantic `Badge` variants (`success`/`warning`/`info` — no DSN source exists for these, sourced independently from the `ui-ux-pro-max` skill's `colors.csv` and verified for contrast, the same posture `DSN-3` used for chart-color gaps), applied to ticket status/priority, task state, one SLA dimension, and ticket escalation (**not** article status or any direction/channel/category/mention badge — only the intake's four named categories); a `lucide-react` iconography pass on primary "New X" actions, `RootLayout` nav, and (via a new optional prop on `Empty.tsx`) every empty state; and a new shared `PageHeader` component replacing 13 duplicated flat page-header blocks with a real two-level type hierarchy above `CardTitle`'s existing `<h2>`s. All static gates (`lint`/`format:check`/`check:rtl`/`build`, backend's 54 tests) passed; live browser-rendered visual confirmation was not possible in that session (no `chromium-cli`/Playwright/Puppeteer available) and is still outstanding.

**Story 51 (`DSN-5`, App Shell Redesign: Sidebar Navigation & Theme Backgrounds) is implemented** (corrected — this line previously read "planned, not yet implemented"; `git log --oneline -- frontend/src/app` shows `bc60bd3 feat: Implement sidebar navigation and theme backgrounds for app shell (DSN-5)` plus a follow-up polish commit `ae0b621`, and `CONVENTIONS.md` § 25's "App shell: sidebar navigation & primitive polish (`DSN-5`, Story 51)" subsection is written in completed past tense). **Story 61 (`DSN-6`, Full UI/UX Audit & Issue Register) is implemented.** Produced `design-system/supportos/UX-AUDIT.md`, a catalogue-only register (no code fixes made — every finding is a catalogued entry, not a patch) covering every route in `frontend/src/app/router.tsx`: 3 public routes, the health/index route, ~35 staff routes across 11 feature areas (customers, tickets, knowledge base manage/browse, accounts, categories, reports, audit log, settings, tasks, the shared 404/route-error-boundary fallbacks), and 9 portal routes, plus the 3 shared shell components (`Sidebar.tsx`, `RootLayout.tsx`, `PublicLayout.tsx`, `PortalLayout.tsx`). Walked against the intake's 6-item heuristic checklist (consistency, feedback, error prevention, recognition-over-recall, minimalism, match-to-real-workflow) plus a responsive and a bilingual pass, per screen. **65 findings** recorded — 5 `critical`, 27 `major`, 33 `minor` — each with a stable `UX-###` ID, one of 7 fixed categories, and an owning story via the fixed category→story mapping: `DSN-7` (`consistency`) 12, `DSN-8` (`interaction`) 18, `DSN-9` (`responsive`) 5, `DSN-10` (`form`) 6, `DSN-11` (`IA`) 12, `DSN-12` (`content`+`bilingual`) 12. The 3 pre-verified shell findings from planning (`UX-001`–`UX-003`, active-nav-state and Reports-link inconsistencies) anchor the register; the remaining 62 came from a per-feature-area walk of every route. Two findings stood out beyond ordinary polish: `UX-005`/`UX-009` (both `critical`) — the public live-chat and web-form submit handlers swallow failures silently, the only way an anonymous customer can start a chat or file a ticket; and `UX-057` (`critical`) — the customer portal's ticket detail page omits the agent-reply conversation thread entirely, so a customer can't see any response until the ticket closes. `UX-034` (`critical`, possible unpublished-article exposure to view-only users) is flagged in the register itself as needing backend verification, since confirming it may fall outside this thread's frontend-only guardrail. No `frontend/`/`backend/` code changed — `git diff --stat` is confined to `design-system/supportos/UX-AUDIT.md` and this overview.

**Story 62 (`DSN-7`, Cross-Feature Consistency Remediation) is implemented.** Resolved 9 of the 12 `consistency`-category rows `UX-AUDIT.md` originally catalogued outright, 2 partially, and confirmed 1 deferred — every landed fix at the shared-component/single-file level per the `DSN-6`–`DSN-13` thread guardrail (frontend-only, no data-flow/API changes). `UX-AUDIT.md` gained a **Status** column (all rows) recording the disposition of every finding this story touched, plus a new row (`UX-066`) for a bug discovered mid-implementation, not present in `DSN-6`'s original walk.

Three of the register's own recommended fixes did not survive verification against the current code and were corrected before (or during) implementation, each recorded in `UX-AUDIT.md`'s own Finding column so the reasoning isn't lost:
- **`UX-036`** — the suggested `body_en`/`body_ar` fallback doesn't exist on `ArticleSearchResult` (the search API never returns it); implemented a translated placeholder (`search.noPreview`) instead.
- **`UX-044`** — the register singled out `TaskFormPage` as the width outlier, but a `grep` across all 10 form pages showed `max-w-lg` is the 6-file majority and `TaskFormPage` already matched it. Narrowed the two genuine outliers, `CategoryFormPage`/`UserFormPage`, to `max-w-lg` instead — `RoleFormPage`/`ArticleFormPage` keep `max-w-2xl`, justified by their permission-grid/dual-language content.
- **`UX-047`** — verified a **false positive** during implementation: `backend/apps/reports/agents.py:30` already defines `MAX_AGENTS = 15`, and `agent_performance()` already sorts descending and slices to that cap (line 121). The finding's premise (an uncapped chart) doesn't hold — no frontend change was made.

Two items are confirmed deferred, both requiring backend changes the `DSN-6`–`DSN-13` guardrail forbids: `UX-030` (FAQs need a backend `status` model field + migration) and the `TaskListPage` portion of `UX-038` (`TaskViewSet` has no `search_fields`, unlike `RoleViewSet`/`CategoryViewSet`, which already did and got search UI wired in this story). `UX-020` also landed partial — 2 of its 3 flagged `SelectTrigger` sites got a `title` fix; the third (`TicketConversation`'s quick-reply picker) was a verified false positive (its selected value always resets to the placeholder immediately after a pick, so nothing is ever truncated).

**One bug was found and fixed outside the register's original scope, while task 1 was already touching the same translation key:** `SlaReportsPage.tsx`, `AgentReportsPage.tsx`, and `CsatReportsPage.tsx` all called `t('title')` for their own `PageHeader`, which resolves the `reports` namespace's bare `title` key ("Ticket Reports") — all three showed the wrong page title in production. Fixed by pointing each at its own existing `sidebarSla`/`sidebarAgents`/`sidebarCsat` key (no new strings), logged as `UX-066`.

`git diff --stat` is confined to `frontend/` and `design-system/supportos/UX-AUDIT.md` — no backend file changed, `python manage.py test` unaffected.

**Story 63 (`DSN-8`, Interaction, State & Feedback Polish) is implemented.** Resolved 15 of the 18 `interaction`-category rows of `UX-AUDIT.md` (2 of those with a corrected approach, 1 a verified false positive requiring no code), deferred 1 for a real backend gap, and left 2 `Open` by explicit product judgment:
- **`UX-007`** (fetch prior chat history on session resume) is **deferred** — the only backend endpoint that reads messages (`MessageViewSet`) requires staff `tickets.view`; no public, session-token-scoped read path exists for an anonymous live-chat customer, and adding one is an API change the guardrail forbids.
- **`UX-039`**'s literal "fetch/display a usage count" has no backend source (`Role`/`Category` serializers return no count) — implemented a copy-only fix instead, rewriting `roles.delete.description` to name the actual consequence, matching `categories.delete.description`'s existing pattern.
- **`UX-040`** is a **verified false positive**: `shared/lib/api/queryClient.ts`'s `MutationCache.onError` already toasts every mutation failure globally, with or without a local `onError` handler — confirmed `useDeleteRole`/`useDeleteCategory`/`useDeleteTask` are all real `useMutation` calls that already get this treatment. No code change.
- **`UX-016`/`UX-028`** (bulk row actions on 5 list pages) recorded as **out of this story's scope by product judgment**, not a guardrail block — a working bulk-delete is technically buildable frontend-only (looping the existing per-row mutation), but `DSN-2` and `DSN-6` both already characterized bulk actions as a feature addition, not interaction-state polish, and building a shared bulk-selection `DataTable` capability is a scope unto itself. Left `Open` in the register with this reasoning appended, not silently dropped.

The two critical findings this story resolved (`UX-005`, `UX-009`) both converted a bare `try/finally` submit handler to a real `useMutation` — `LiveChatWidget`'s `StartForm` and `WebFormPage`'s `WebForm`, the only two ways an anonymous visitor can start a chat or file a ticket — which is what makes the global mutation-failure toast actually fire for them instead of failing silently. The unsaved-changes guard (`UX-025`) required more than the plan's sketch: `useBlocker` returns a blocker object with no UI of its own, so the hook drives it through the shared `useConfirm()` dialog (the same confirmation surface every destructive action in this app already uses) rather than leaving navigation silently stuck — and both `FaqFormPage`/`ArticleFormPage` now call `form.reset(values)` on successful save, since without it the guard would have blocked the post-save redirect it itself introduced. `ChartFrame`'s export-gating (`UX-049`) fixed all 5 report pages from one shared-component edit. A pre-existing `UserFormPage.tsx`-confirmed pattern (icon-only remove buttons needing a real `aria-label`) also applied to `SettingsPage.tsx`'s `StringListField` (`UX-053`).

`git diff --stat` is confined to `frontend/` and `design-system/supportos/UX-AUDIT.md` — no backend file changed, `python manage.py test` (54/54) unaffected.
